# S34 — Connector actions through approvals Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An integration's granted action runs through the existing approval path. Its preview and its run are both jobs on the integration's Edge Agent, approvals follow the workspace's policy, and the co-analyst is offered these actions.

**Architecture:** A workspace-aware action resolver replaces the app-wide registry wherever a proposal's action is looked up. For `<prefix>__<action>` it compiles the action of that workspace's enabled integration, if the action is granted. Each compiled role dispatches a `connector.action.<step>` job to the integration's agent and waits for its answer. That answer has already been checked by the SDK's validators. Approvals are checked against a per-workspace policy (default: write = analyst or admin, destructive = admin).

**Tech Stack:** FastAPI, asyncpg, Postgres (S31 jobs), `auspex-sdk`, the S33 Edge Agent.

**Spec:** docs/superpowers/specs/2026-11-02-s34-actions-design.md. Baseline: docs/probes/2026-11-02-s34-baseline.md.

## Global Constraints

- Every write to a customer system goes through an approval (D-014, D-024). Widening `EXECUTABLE_SYSTEMS` is code plus an adversarial review.
- Nothing a connector ships runs in the app (D-062). The structural tests stay green.
- Tenant isolation is an invariant. A prefix resolves only in its own workspace, and every new table and route gets a cross-tenant test.
- Wait bounds: the dry run waits 30 s; execute and undo wait 60 s; observe waits 30 s. Proposing when the dry run times out is refused in words, and nothing is filed.
- Default policy: `write` may be approved by an analyst or admin; `destructive` only by an admin.
- Grants: a new integration has none. A grant of an action the pinned manifest lacks is refused.
- One fix or feature per commit, each with tests, and the README count kept current.
- Scope lock: no `fetch` schedules (S35).

## Review Focus

1. A prefix from another workspace, a disabled integration, or an ungranted action must not resolve. Proposing, approving, executing and undoing it are all refused. (Task 3)
2. A lost execute result must never run the action twice. The re-claimed job is the same job, under the same idempotency key, and the mock SIEM is called once. (Task 5)
3. An approver the policy does not allow is refused before the row moves, and the decision records the rule in force. (Task 4)
4. An approved connector action is refused before its claim, with its own reason, when:
   - the agent is offline, revoked or has never connected;
   - the integration is disabled;
   - the action is no longer granted;
   - the package changed.

   (Task 6)
5. An agent posting an action result for another workspace's job, or one whose shape breaks the manifest's output, is refused or failed in words. (Task 5)
