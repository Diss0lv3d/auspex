# S33 — Integrations, the Edge Agent, and Test connection Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An admin configures an integration and enrolls an Edge Agent, and "Test connection" runs the reference connector in the agent's container and shows the validated answer.

**Architecture:**
- **Core:** two new tables, `integrations` and `edge_agents` (plus enrollment tokens); admin routes; and an agent-only edge API. The edge API offers a long-poll claim over S31's queue, a result post validated by the SDK, a heartbeat that extends leases, and package-by-hash.
- **Agent:** a separate package, `auspex/edge/`, with its own image. It fetches packages by hash, re-hashes them, and runs each command through a shared SDK entry point (`auspex_sdk.run`) in a subprocess with a timeout. Secrets go to that subprocess on stdin.

**Tech Stack:** FastAPI + asyncpg + Postgres (S31 jobs), the `auspex-sdk` distribution, httpx, Docker compose (dev profile).

**Spec:** docs/superpowers/specs/2026-10-28-s33-edge-agent-design.md (decisions 1–11 and "Settled after the builder check" 1–10). Baseline: docs/probes/2026-10-28-s33-baseline.md.

## Global Constraints

- **D-062:** nothing a connector ships runs in the app process. `tests/test_connector_structure.py` stays green. `auspex/edge/` may import `auspex_sdk`, but nothing from `auspex` except `auspex.edge`. The core never imports `auspex.edge` (a structural test).
- **D-063:** a secret value never reaches a row, a response, a log or the page. A config's secret field holds only `secret:<name>`.
- **Tenant isolation:**
  - Every new table carries `workspace_id`.
  - Every new route and every edge endpoint gets a cross-tenant test.
  - An agent claims, reads and posts only within its workspace and only for the integrations that name it.
- **Auth boundaries:**
  - The agent credential reaches only `/api/edge/*`.
  - A person's token reaches none of `/api/edge/*` except the admin agent routes, `/api/edge/agents*`.
- **`connector.test` job kind:** `max_attempts=1`, `lease_seconds=90`. The subprocess timeout for `test` is 60 s.
- **Health:** online under 60 s since the last heartbeat; stale under 300 s; offline after that.
- **Enrollment tokens:** shown once and valid 24 h. Agent credentials are hashed with `hash_api_key`, under a new prefix `apa_`.
- **New env vars** go into `.env.example` and `docs/ENV_VARS.md`. **New packages** go into `pyproject.toml` and the Dockerfile skeleton.
- **Commits** take the form `feat|fix|chore(scope): summary`, one concern each, with tests in the same commit. The README test count is updated.
- **Scope lock:** no connector actions run in S33 (they are S34's), and no `fetch` schedules (S35's).

## Review Focus

1. An agent posting a result for another workspace's job, or for a job it no longer holds (lease lost, revoked), must be refused and leave the job's state as it was. Task 4 owns the test.
2. A config holding a secret value instead of `secret:<name>`, or naming a field the manifest lacks, must be refused at write. The job row then never carries a value. Task 2 owns the test.
3. A package whose bytes do not hash to the job's `content_hash` must not run. The test fails as `error`, naming both hashes. Task 6 owns the test.
4. A secret value must not appear in any response, log, job row or audit row, even when the connector prints it to stdout. Tasks 6 and 9 own the scan.
5. An agent offline or revoked, or an integration disabled: "Test connection" answers in words and never queues a job that cannot run. Task 8 owns the test.

### Task 4: The edge API — claim, result, heartbeat, package

**Files:** Create `auspex/edge_api/routes.py` and `auspex/connectors/kinds.py` (the `connector.test` `JobKind`; its handler is never called in-app). Modify `auspex/jobs/queue.py` (`extend_leases(pool, *, claimer, seconds)`). Test `tests/test_edge_api.py`.

**Interfaces:**
- **Consumes:** `claim`, `complete` and `fail` (`queue.py:179/246/262`); `ClaimScope`; `AgentAuth`.
- **Produces:**
  - `POST /api/edge/claim`: a long-poll of at most 25 s, retrying `claim` each second with scope `kinds={"connector.test"}`, `workspace_ids={agent ws}`, `integration_ids={enabled integrations naming this agent}`, and `claimer=f"agent:{id}"`. It returns `{job: {id, kind, token, payload}}` or 204.
  - `POST /api/edge/jobs/{id}/result`: body `{token, result | error}`. A result is validated with `auspex_sdk.validate.check_test` (Task 5) and then `complete`. An invalid result or an error goes to `fail` with the reason in words.
  - `POST /api/edge/heartbeat`: stamps `last_heartbeat_at` and calls `extend_leases`.
  - `GET /api/edge/packages/{content_hash}`: the bytes, only for a hash an enabled integration of this agent pins; otherwise 404.

- [ ] **Step 1:** Write the failing tests (Review Focus 1), then run them and watch them fail:
  - the claim returns only this agent's integration's jobs;
  - another workspace's job is never claimed;
  - a disabled integration's job is not claimed;
  - two agents racing get one winner;
  - a result with the wrong token, for another workspace's job, after the lease is lost, or from a revoked agent is refused, and the job is unchanged;
  - an invalid result fails the job in words;
  - a heartbeat extends only this agent's leases;
  - a package for an unpinned hash, or another workspace's, answers 404;
  - the long-poll returns 204 within its bound when idle (with the bound patched short).
- [ ] **Step 2:** Implement.
- [ ] **Step 3:** Pass. Commit `feat(edge): the edge API -- a scoped long-poll claim, validated results, heartbeats that hold leases, packages by hash`.
