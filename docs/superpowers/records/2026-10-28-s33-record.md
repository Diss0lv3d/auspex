# S33 record — every choice made, and what was followed

Session S33 (backend track), owned by Hunaiza; Burhan handed it over fully on
2026-10-28 (D-059). It was built with Claude on the branch `s33-edge-agent` and
goes to `staging` as one PR.

What S33 delivers: integrations, the Edge Agent, and "Test connection" running
end to end through a real agent container.

## 1. What S33 built, in plain words

- **Step 0: Burhan's ten review findings on S32 are fixed**
  (docs/probes/2026-10-28-pr43-review.md, each row marked with its commit). In
  short:
  - a connector's four roles must be four different functions;
  - a compiled action refuses any workspace but its integration's own, and
    refuses before anything is sent, recorded as "failed, nothing landed";
  - connector text loses hidden and direction-reversing characters;
  - an undo refuses a connector that changed since the approval;
  - the catalogue refuses an unstorable manifest in words;
  - a re-upload cannot silently change an offer, even in a race;
  - a provider offers each connector from one workspace only;
  - secrets are hidden in the HTTP library's own logs;
  - the SDK version is no longer part of a connector's identity (D-072).
- **Integrations.** An admin configures a connector the workspace may use,
  names the Edge Agent that runs it, and gives secret fields as
  `secret:<name>` only. The settings are checked against the connector's own
  schema on every write.
- **Edge Agents.** An admin creates one and is shown a one-time enrollment
  token (valid 24 h). The agent spends it once for its credential, which is
  stored hashed and reaches only the edge API. An admin can revoke it.
- **The edge API.** The agent long-polls for its own integrations' jobs,
  posts results (checked with the SDK's shared validators), heartbeats (which
  also extend the leases it holds), and downloads packages by their hash.
- **The agent** (`auspex/edge/`, its own image `Dockerfile.edge`). For each
  job it:
  1. fetches the package by hash and re-hashes it before running anything;
  2. reads its secrets file again (mode 0600);
  3. hands the command only the secrets its settings name;
  4. runs the command in a subprocess with a time limit;
  5. posts the answer, with secrets hidden.
- **Test connection.** It distinguishes **ok**, **failed** ("the SIEM said
  no") and **error** ("we could not ask"). Only one test is in flight per
  integration. It is refused in words when the integration is disabled, or the
  agent is revoked, offline or has never connected.
- **Audit.** Registering a connector, and creating, changing or disabling
  integrations and agents, are recorded (D-073; TD-068 closed).

## 3. Hunaiza's calls

1. **D-072: the SDK version that built a connector is not part of its
   identity.** It is recorded in the zip's comment, which the hash does not
   cover.
2. **Each integration names one Edge Agent.** Only that agent runs its jobs.
3. **Running connector actions waits for S34**, as the plan says. S33 is Test

4. **An integration is disabled, never deleted.** Its prefix is never reused
   in its workspace, so an old approval never points at a different
   integration.

## 4. Calls made during the build (Claude's, where the docs were silent)

Each call below ends with what it costs if it turns out wrong.

- **No `actor` argument on register.** `register` works out its actor itself:
  the CLI, or the user with their home organization read under lock. That
  avoids B-034's stale home. *Cost if wrong:* a signature change later.
- **Task order 1, 3, 2, 5, 4, 6, 7, 8, 9.** Integrations need the agents table
  first, and the edge API needs the shared validators first. *Cost:* order
  only.
- **Prefixes follow the shared wire-name rule** (capitals allowed, as tool
  names are). *Cost:* a stricter rule later.
- **An agent's own events are recorded as `system`, naming the agent** (D-073).
  The actor kinds stay unchanged.
- **Health thresholds.** Online under 60 s since the last heartbeat, stale
  under 5 min, then offline. Testing through an offline or never-connected
  agent is refused; testing through a stale one is allowed.
- **A test is never retried.** `max_attempts=1`, a lease of 90 s, and a 60 s
  command limit.
- **The job carries what the agent runs**, including the settings with secret
  names. There is no settings endpoint. The agent checks the settings again
  before running.
- **The agent receives only the secrets its settings name**, never the whole
  file.
- **The runner's contract** (`auspex_sdk.run`). One JSON job in on stdin, one
  JSON answer out. Everything the connector prints, logs or raises is captured
  and redacted.
- **Edits cancel queued tests.** Disabling an integration, or changing its
  agent or package, cancels its queued tests in the same transaction.
- **The image check is a `ci.sh` step** (images are built after pytest).
  `ci.sh` makes `.edge-dev/` itself, as the user.
- **The dev agent runs as the host user**, with its cache in `/tmp`, so it can
  read the host's 0600 secrets file.

## 5. Left on purpose

- **TD-071:** roles are checked as written, not as imported. Due before S34.
- **TD-072:** no local install for air-gapped sites yet (D-062).
- **TD-073:** each agent holds one long-poll request.
- **TD-074:** a swapped agent's running test waits out its lease.
- **The live check's offline state** was reached by ageing the heartbeat by
  SQL, not by waiting five minutes. This is stated in the probe.

## 6. What S34 picks up

S34 makes connector actions run through approvals, using what S33 built:
- the edge API's claim scope;
- the runner;
- the shared validators;
- the integration's agent and pinned hash.

What S34 must build:
- `check_executable` admits connector systems, and an approval is bound to its
  integration (a prefix is never reused, so the prefix plus workspace is
  stable);
- dispatch runs `actions[].execute`;
- the core validates action envelopes with `auspex_sdk.validate`;
- TD-071 before any action runs.
