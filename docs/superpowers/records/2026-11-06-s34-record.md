# S34 record — every choice made, and what was followed

Session S34 (backend track), owned by Hunaiza; Burhan handed it over fully on
2026-10-30 (D-059). It was built with Claude on the branch `s34-actions`, inline (no
helper agents while building, Hunaiza's instruction). It goes to `staging` as one PR.

What S34 delivers: a connector's actions run through the existing approval path on the
customer's Edge Agent, each client's approval policy decides who may approve, and the
co-analyst can propose them in chat.

## 1. What S34 built, in plain words

- **SDK carries first.**
  - TD-071: an action's roles that import as one function are refused at build.
  - TD-077: the runner and the test harness run a command through one helper, and
    the job's idempotency key reaches the connector.
- **Grants.** An integration runs only the actions an admin granted, none by default.
  - Granting an action the pinned package lacks is refused.
  - Grants are audited.
  - Moving the integration to another package clears them (review #1).
- **Actions resolve by workspace.** `siem1__close_alert` means something only in its
  own workspace, for an enabled integration with that action granted.
- **The approval policy.** By default, analysts and admins approve `write` and only
  admins approve `destructive`.
  - A workspace's admin can narrow it per risk level: which roles, and whether the
    MSSP's staff may approve at all.
  - It is checked inside the approval itself, so a refused approver changes nothing.
  - The rule in force is recorded on the proposal (D-075).
- **Dispatch.** Every step (preview, run, undo, check) is a job on the integration's
  Edge Agent.
  - The core waits 30 s for a preview or a check, and 60 s for a run or an undo.
  - Each answer is checked against what the connector declares.
  - A run never happens twice under one key.
  - A job claimed and never answered reads "effects unknown" (`incomplete`, which can
    be undone), never `failed` (review #2).
- **Refusals before anything runs.** An approved connector action is refused, each
  with its own reason, when:
  - the agent is offline, never connected or revoked;
  - the integration is disabled;
  - the action is no longer granted;
  - the package changed.

  The same refusals stop a proposal, so nothing waits on a dead agent. D-077: a
  connector action may touch its own connector's system, and nothing else.
- **The co-analyst** is offered its workspace's granted actions. The tool text is
  composed by code from the manifest, flattened and capped.
- **Engine.** A new key works. Burhan moved the dev model to **glm-5.3-flash**
  (D-076), checked live: tool calling works and it runs about half the old speed.
- **Live:** a real chat turn proposed "close alert A-1001".
  - The admin approved it, the real Edge Agent closed the alert in the stub SIEM
    once, and the undo reopened it.
  - The secret appeared in no log (docs/probes/2026-11-06-s34-live.md).
