# 2026-10-28 — B4: B-027 before the fix (extract() is O(matches × spans))

Measured on `b4-bugs` (`30f7fb2`), host `.venv`, best of 3, with the inputs
B3's review named (each just under the chat route's 32,000-character cap):

```
emails      len= 31997 best of 3:  1089.0 ms
url+ip      len= 31994 best of 3:   535.2 ms
url+domain  len= 31990 best of 3:   710.7 ms
```

The cause: `_spans_overlap` (`auspex/classify/observables.py:266`) walks
every earlier span for each match, so each pass costs matches × spans. Every
span list it is given holds disjoint spans (each pass skips a match that
overlaps an earlier one), which is what lets a sorted index answer the same
question by bisection. `extract()` runs on the chat route's event loop.

## After the fix

`_Spans` (a sorted, disjoint index; `overlaps` is one bisection) replaces the
walk. Growth with 4x the matches, `tests/_timing.elapsed_ms` (best of 3):

```
before  emails 14.2x   url+ip  8.3x   url+domain  9.8x
after   emails  4.6x   url+ip  2.4x   url+domain  4.3x
```

At the cap the passes now take 84–98 ms; what remains is linear (the refang
pass and building observables), outside this bug. The test pins growth
(`B027_MAX_GROWTH = 6.5`), not wall-clock, so a slow runner does not flake it:
`test_b027_extract_grows_linearly_in_its_matches` failed on the old code for
all three inputs. `test_b027_the_index_finds_exactly_what_the_walk_found`
extracts 400 seeded random mixes of every observable shape with the index and
with the old walk, and gets identical results.

## Review, and the tests made firm

The fresh review found `_Spans` correct (every set disjoint by construction; 0
differences on about 210,000 fuzzed texts) but the tests weak:

- the growth test was wall-clock at 4x, and failed 1-3 times in 6-8 under heavy
  CPU load, with only about 2x between linear and the old walk;
- the differential let five boundary mutants of `_Spans` through.

Now the growth test compares 8x the matches in CPU time (`time.process_time`,
best of 3) against a bound of 14. Measured, CPU time:

```
new  emails 8.2-8.7x   url+ip 8.0-8.1x   url+domain 8.1-8.4x
old  emails 37.2x      url+ip 21.2x      url+domain 29.5x
```

It passes 5/5 runs with 16 busy loops on the machine, and fails all three
inputs on the old code. Two direct tests of the index were added: written
boundaries (touching spans, one shared character, out-of-order `add`,
`__add__`) and 300 shuffled disjoint sets against the walk. The four boundary
mutants (`bisect_left` on the ends, `<=`, an unsorted `add`, `start + 1`) each
fail two of them now; the fuzz pieces gained bracketed IPv6 URLs, an
IPv4-mapped address, userinfo and a hash inside a URL.
