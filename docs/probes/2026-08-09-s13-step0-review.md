## Findings (all executed, all fixed)

**1. NUL byte in a paste → live 500 (security/robustness).**
Live container, POST `/api/investigations` with `U+0000` in the Subject
header and body → `500 Internal Server Error`;
`asyncpg.exceptions.UntranslatableCharacterError: unsupported Unicode escape
sequence` in app logs (Postgres text/jsonb cannot represent U+0000 at all).
Fix: strip NUL at the route boundary before parsing, so parsers, snapshot,
and persisted statements see the same text; an all-NUL paste falls through
to the honest 422. Post-fix live re-probe: **201** on the rebuilt container.

**2. Duplicate hypothesis keys double-render weights (correctness).**
`score_matrix` with a 5-tuple carrying two TRUE_POSITIVE rows: weight
normalization ran over unique keys but rendered per row — displayed weights
summed to **1.300100**, two TP rows each showing the full TP weight. DB
UNIQUE holds this at persistence; nothing held it for other callers (S13
adds callers). Fix: `score_matrix` raises ValueError on duplicate keys.

**3. Hand-edited cells jsonb crashes or distorts (correctness).**
Two arms, both executed against Postgres round-trips:
- string cell `"2"` → `TypeError: '<' not supported between instances of
  'str' and 'int'` — **every GET of that investigation 500s** (load-brick
  shape, same family as the S12 retired-kind finding);
- int `-7` → inconsistency **6.2**, a manufactured hard contradiction, and
  FALSE_POSITIVE **rejected** — 3.5× the pinned cell maximum accepted
  silently. `CELL_MIN`/`CELL_MAX` were declared in types.py and enforced
  nowhere. Fix: `_cells_from_json` skips (with a warning) any cell that is
  not an int in −2..+2 or None; bool excluded explicitly (json true/false
  would count as 1/0). Same tolerance doctrine as retired kinds/keys.

**4. Concurrent lookup folds duplicate the evidence trail (correctness).**
`asyncio.gather` of two run_lookup sequences (load → assess → enrich →
add_evidence) with a 150 ms in-flight window: both chose the same top
candidate, both folded, trail held **2 identical ENRICHMENT_MALICIOUS rows**
— scored as independent facts, FP inconsistency **5.0** instead of 2.5.
Fix: `add_evidence` takes `FOR UPDATE` on the investigation row (serializes
folds) and dedups observable-linked rows per (kind, source, obs_id) — a
candidate is only looked up once (coverage retires it), so an identical
incoming row is always a concurrent duplicate. Returns rows actually
written; regression pins written == [0, 1] under gather.

**5. recipient_domains unbounded in the snapshot (bounds honesty).**
A 9.4 KB email paste with 300 recipients → snapshot stored and echoed all
**300** domains, no truncation marker — the one paste-controlled list the
S12 finding-8 caps missed (iocs: capped at 200 + named). Fix: cap 50 +
named `recipient_domains_truncated`. The victim filter runs on the full
envelope at parse time — the cap bounds only the display snapshot.

**6. `weight` read as probability (honesty).**
The API rendered `weight` bare; matrix.py doctrine says plausibility weight
(2^(−inc/2) normalized), NOT a probability — no base rates anywhere. Renamed
to `plausibility_weight` pre-promote, while the surface has zero consumers.

**7. Zero-hypothesis edge borrowed the wrong messages (honesty, minor).**
`score_matrix((), evidence)` → "fits every surviving hypothesis equally";
`rank_lookups` → "only one hypothesis survives". Both statements about sets
that don't exist (reachable only by hand-deleting rows). Fixed both
messages to say what is true.
