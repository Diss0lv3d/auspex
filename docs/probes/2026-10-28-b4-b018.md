# 2026-10-28 — B4: B-018 before the fix (a URL keeps its credentials)

Reproduced in the running app container (`staging` at `cc85b0e`), with
placeholder credentials only:

```
$ docker compose exec -T app python -c "from auspex.classify.observables import extract; ..."
[('url', 'http://analyst:PLACEHOLDER-PW@evil.example.com/drop.exe')]
[('url', 'https://bob@phish.example.com:8443/login?x=1')]
```

The cause: `_normalize_url` (`auspex/classify/observables.py:269-282`)
lowercases the host and keeps the userinfo (`user:pass@`). The observable's
`value` is what is looked up at URLhaus and upserted into `observables`, so
the credential travels to a third party and into storage. `residual` blanks the
whole URL span, and `Observable` carries no raw text, so `value` is the only
carrier.

## After the fix, and its review

The first fix (`d78bc43`) dropped the userinfo inside `urlsplit`'s netloc. The
fresh review found three leaking shapes left: a URL `urlsplit` refuses (an
unbalanced `[`) fell back to the raw text, and a `/`, `?` or `#` inside a
password ended the netloc early, leaving the credential in the path, query or
fragment. The second fix removes the userinfo by text before parsing
(`_drop_userinfo`); all twelve fixture inputs, the reviewer's forms among them,
pass. Logged, not fixed here: B-033 (the stored message text, and rows saved
before the fix).

## Burhan's review of PR #50, and the third fix

The second fix's fallback (`_PORT_RE`: a non-numeric `host:x` followed later
by `@` read as `user:pass`) took the host from text after the authority, which
whoever wrote the link chooses. Reproduced on `b4-bugs` before the third fix:

```
'http://evil.com:x/p?r=@google.com' -> ['http://google.com']
'http://2001:db8::1/a?e=x@y.com'     -> ['http://y.com']
'http://paypal.com\@evil.com/'       -> ['http://evil.com/']
```

The lookup and verdict would land on a host the link never reaches. The third
fix follows the URL standard (Burhan's rule): for http(s) the authority ends at
the first `/`, `?`, `#` or `\`, the userinfo is everything up to the last `@`
inside it, and nothing after the authority becomes the host. The fallback and
the dead `rsplit("@")` in `_normalize_url` are gone; `_drop_userinfo` alone
owns the rule. The three inputs are pinned to keep their host
(`test_b018_the_host_is_never_taken_from_after_the_authority`); the three
"password holding a delimiter" cases now parse as the standard reads them
(`test_b018_a_password_holding_a_delimiter_parses_by_the_standard`, TD-070);
the nine that must drop the credential still do. All six new assertions
failed first.
