# 2026-10-28 — B4: B-030 before the fix (the quote-line carve-out is quadratic)

Measured on `b4-bugs` (`29da40e`), host `.venv`, best of 3
(`tests/_timing.elapsed_ms`):

```
31999 inspect: 2875.2 ms content
quote-line finditer alone: 2714.8 ms
```

Input: `"you are now x" + "\n" * 31985 + "x"`. The review measured about 0.4 s
on Burhan's machine; this one is slower, and the shape is the same. The
cause: `_QUOTE_LINE_RE` (`^\s*>.*$`, MULTILINE; `auspex/guard.py:235`)
runs only after a rule hits (the carve-outs). At every line start in a
newline run `\s*` crosses the newlines to the end of the run before failing
on `x`, so the scan is quadratic in the run.

The pinned stall inputs (`tests/fixtures/classify/b010_redos.json`) never
hit a rule, so this half of `inspect()` was never timed. B4 adds
`guard-rule-hit-newlines` (the same input at exactly 32,000 characters).

## After the fix

`_quote_line_spans` (`auspex/guard.py`) replaces `finditer` on the
carve-out: at each line start it finds the first non-whitespace character
once; `>` there is a match to that line's end, anything else sends the scan
to the next line start past it. Same spans, by Burhan's rule for this family
(B-029):
`test_b030_the_quote_line_scan_finds_what_finditer_finds` compares the two on
14 written edges and 3,000 seeded random texts of line breaks, `\s`
characters and `>`.

```
inspect after: 20.5 ms content
```

The new fixture input `guard-rule-hit-newlines` failed first at 4,050 ms in
`test_b010_the_pinned_inputs_clear_the_chat_routes_text_pass_in_time` (its
1,000 ms budget, in a child process), and now passes.
