## B-010 — the classify pass can be stalled by crafted input (GitHub #38)

### Reproduced first

`redos_timings.py` times each rule, and the whole pass, at 2,000 to 32,000
characters (the chat route's message cap). On the host (`before.txt`), at
32,000 characters:

| Input | Rule | Before |
|---|---|---|
| `"x" + spaces + "x"` | refang `[.]` / `[@]` | 16.4 s / 8.5 s |
| `"hi" + spaces + "x"` | `_GREETING_RE` | 102.6 s |
| `"a." * 16000` | `_DOMAIN_CAND_RE` / `_EMAIL_RE` | 48.6 s / 4.1 s |
| same | `extract()` / `classify()` | 51.1 s / 23.0 s |
| `"hi" + spaces + "x"` | `classify()` | 101.5 s |

Live in the running container on the old image (`container-before.txt`):
`classify("hi" + spaces + "x")` 41.8 s, `extract("a." * 16000)` 9.4 s.

### The fix

- **Refang rules.** The leading `\s*` let every position inside a whitespace
  run start an attempt that scanned to the run's end. It is now
  `(?:(?<!\s)\s++)?`: whitespace is taken only from where its run begins, or
  not at all. The leftmost match never started mid-run, because the match
  before consumes a run whole. Inner and trailing whitespace is possessive.
- **`_GREETING_RE`.** Possessive throughout. `\s*[!.,\s]*$` split a run every
  way between its two parts before failing at the last character.
- **`_DOMAIN_CAND_RE`, `_EMAIL_RE`.** The patterns are unchanged.
  `extract()` searches them with `_domain_candidates` / `_email_candidates`,
  which try the rule at the same positions in the same order as `finditer`,
  but skip the positions proven to fail after a failure:
  - for a domain, the chain of `label.` segments reachable from the failed
    start, and the starts after a hyphen inside those labels;
  - for an e-mail, the rest of the local-part run.

  The bug's note suggested letting a candidate start only at the beginning of
  a dotted run. That would have changed the matches:
  `my_host.evil.com` → `evil.com` today, nothing after. So it was not used.
- **`_ANALYTICAL_INITIAL_RE`** (the fourth rule). B3's review of the fix found
  `"." + spaces + "x"` at 64.3 s. Hunaiza's call: fix it inside B-010. The
  rule is now `(?:^\s*+|[.!?]\s++)`; `\s+\s*` is `\s+`.

### Proof

- **Tests failed first:** the timing tests (8,000 characters, 50 ms), and the
  full-size pinned inputs (`tests/fixtures/classify/b010_redos.json`) run
  through `extract()` and `classify()` in a child process with a 10 s timeout.
  They pass after the fix.
- **Same matches.** `diff_fuzz.py` compared the six rules before and after on
  200,000 generated and 501 real inputs (every string in `tests/fixtures`):
  **0 differences** (`diff_fuzz.txt`). Seeded fuzzes in the tests pin the same.
  The review ran its own targeted fuzz (240,000 strings: 61–65-character
  labels, edge hyphens, `_`, the Kelvin sign, long s, Unicode spaces, `\r\n`):
  0 differences.
- **Mutants 7/7 caught:** each fix reverted in turn, and the two scans
  skipping too little and too far.
- **Live, in the rebuilt container** (`container-after.txt`), at 32,000
  characters: `classify()` 11.9 ms (hi + spaces), 11.6 ms (. + spaces),
  22.1 ms (a.a.a.); `extract()` 10.4 ms and 16.2 ms. The raw "domain rule" and
  "email rule" rows still time the unchanged patterns called directly;
  nothing calls them that way any more.

## B-024 — arrow keys on the closed switcher switch at every step (GitHub #39)

### Reproduced first (`before-run.txt`)

`seed.sh` made an MSSP with three clients, and an analyst who can enter all
four workspaces. In headless Chromium on Linux against the container, focusing
the closed `<select id="workspace">`:

| Key | Switch requests | Reloads |
|---|---|---|
| ArrowDown | 1 | 1 (into alpha) |
| ArrowDown | 1 | 1 (into bravo) |
| ArrowUp | 1 | 1 (back into alpha) |

### Options, and Hunaiza's pick

1. **A Switch button** (picked): choosing only selects, the button switches.
   It behaves the same in every browser and is the standard accessible
   pattern.
2. Enter to switch: arrows only select, Enter or a pointer pick switches.
   This depends on telling keyboard from pointer, which browsers do
   differently.

### The fix

- `change` only refreshes the button (`syncSwitch`). Its click is the only
  way into `switchTo`.
- `switchReady(selectedId, me, held)` (`js/shell-logic.js`, tested under
  Node) is true only for a workspace other than the active one, once `/me`
  has answered, while nothing holds the page.
- The button is named "Switch workspace" for a screen reader. It sits 8 px
  from the select (`base.css`). Its state is computed on render too, because
  the select can show a workspace that is not the active one.
- D-070 holds: one switch at a time, and a reload without the hash.

The first build broke the page: `showSignedOut` has its own `const go` (the
Sign in button), so naming the new button `go` raised "Cannot access 'go'
before initialization". The live check caught it; the source-reading tests
could not. The button is `switchButton`.

### Live after (`after-run.txt`, `phone-switch.png`, `after-switch-button.png`)

- Three arrow presses: **0 switch requests, 0 reloads**.
- Two arrows to charlie, Tab (focus lands on `switch`), Enter: exactly one
  switch, into charlie.
- A pointer choice plus a click: exactly one switch.
- On a fresh page the button is disabled. Choosing another workspace enables
  it; choosing the active one again disables it.
- Phone width does not overflow, and there are zero CSP violations.
- `cleanup.sh`: 0 users and 0 organizations left.

### Proof

- The tests failed first: `switchReady` was missing, and the source pins
  (`change` never reaches `switchTo`).
- Mutants 6/6 caught: `change` switching again; ready for the active one;
  ready while held; `setBusy` not holding the button; no state on render; a
  failed switch leaving the button enabled.

### B-029: the input guard (item 1)

`guard.inspect()` runs before `classify()` on `POST /api/chat`, over the
folded text and the raw text. Before the fix (`before.txt`), at 32,000
characters:

| Input | `inspect()` before | after (`after.txt`) |

| `"." + spaces + "x"` | 67.4 s | 10.8 ms |

- `_spans_of` tries the two run-led rules at the positions `finditer` would,

  test the same text after it.
- `persona_override`'s prefix is possessive. Inside one attempt,
  `[.!?]\s+\s*` was splitting a run every way.
- The raw `finditer` rows in `after.txt` still time the rules called directly.
  `inspect()` no longer calls them that way.

**Same answers.** `diff_fuzz.py` ran the guard at `9475752` (imported as a
separate module) against the new one. On 200,000 generated inputs, heavy on
newline, whitespace and Unicode-space runs, plus 501 real fixture strings, it
compared:
- the whole `inspect()` answer (verdict, rule and reason);
- both rules' spans over the raw text and over the folded text.

It found **0 differences**. The tests also carry a seeded fuzz against the
rules' text before the fix, which is byte-identical to `9475752`. Mutants:
5/5 caught.
