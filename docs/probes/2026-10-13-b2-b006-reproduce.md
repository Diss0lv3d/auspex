## Root cause

Two gaps, and the turn falls through both.
- **The data.** For an indicator that sources answered for and none
  signalled, the agent's tool result carries a bare `"signals": []` beside
  `"sources_answered": 5`. Nothing in it says what that means.
  - The payload's own comment covers the other case: an indicator that was
    not looked up gets `not_checked`, "because a model given 'no signals'
    would call it benign" (`auspex/agent/capabilities.py:300-303`).
  - Looked up with no signal, it says nothing, and the model calls it benign.
- **The mode.** "dig deeper" resolves to `general` (the resolver reads only
  the current message). general's directive does not carry ioc_enrichment's
  hard rule, "Never assert a reputation verdict you do not have evidence
  for; absence of data is 'unknown', not 'benign'" (`auspex/modes/catalog.py`).

Burhan's call: fix both, in code and in the prompt.

## The fix (`fce2f55` code, `c80bf29` prompt), live

**What changed.**
- **The data.** A looked-up indicator with no signal now carries
  `"reputation": "unknown"` and the line "no signal from 5 connected
  sources: reputation unknown, which is not a benign verdict". When no
  source answered, the line says "not checked" instead.
- **The prompt.** general now carries ioc_enrichment's no-data rule, from one
  shared constant.
- **Proof.** `./ci.sh` green at 1381 tests. 4 mutants, 4 caught.

**Live**, the same probe in-process (`b2-b006/raw-repro-after.log`,
`.jsonl`), 3 fresh chats. The model read the new fields in every run. These
are the sentences that make a reputation claim:

| | before (3 runs) | after (3 runs) |
|---|---|---|
| a benign verdict or risk level ("Clean reputation", "Risk Level: Low", "safe", "not a malicious IP") | **3/3** | **0/3** |
| says the reputation is unknown | 0/3 | **3/3** (2 add "not benign") |
| calls it "legitimate" Google infrastructure | 3/3 | 3/3 |
| "clean" still used, of the results | — | 1/3 ("despite the clean threat intelligence results") |

From after-run 2: "**Reputation Status:** Unknown (not benign)" … "the
'unknown' rather than 'benign' reputation status indicates that this IP hasn't
been thoroughly vetted or classified as safe".

**Residual, stated.** The model still infers that the address is
"legitimate" from who operates it, and in runs 1 and 3 partly from the absence
of signals ("The absence of any threat intelligence signals suggests this is
a legitimate Google-owned IP address"). That is a claim nobody supplied, which
is the deferred fabricated-specifics item, next to B-005, and not re-scoped
here.
