# Probe: NVD CVE API 2.0 — delta querying (S7 ingestion)

- **Date:** 2026-07-17
- **Target:** `https://services.nvd.nist.gov/rest/json/cves/2.0` with
  `lastModStartDate`/`lastModEndDate` (keyed — `apiKey` header, see the
  2026-07-17-nvd-api.md addendum for key mechanics; requests spaced ≥3 s)
- **Why:** S7's ingest scheduler pulls modified-CVE windows to keep the KB
  current across host downtime. Window/pagination/error mechanics measured
  before coding.

## Measured

### 1-day window volume + envelope

`?lastModStartDate=2026-07-16T00:00:00.000Z&lastModEndDate=2026-07-17T00:00:00.000Z&resultsPerPage=3`
→ HTTP 200, 1.5 s:

```
resultsPerPage: 3, startIndex: 0, totalResults: 768,
format: "NVD_CVE", version: "2.0", timestamp: "2026-07-17T12:23:58.930"
vulnerabilities[].cve: same per-CVE shape as the single-CVE probe
  (id, lastModified, vulnStatus, descriptions[], metrics.*, references[])
```

**~768 modified CVEs in ONE ordinary day.** A multi-day gap is thousands of
docs — ingestion must page, not slurp.

### Pagination

Same window, `startIndex=3&resultsPerPage=3` → 200; `totalResults` stable
(768), next 3 distinct CVEs, no overlap with page 1. Page order is
lastModified-ascending-ish but NOT contractual — treat pages as a set;
upsert by id makes replays harmless.

### Caps and error shapes (all live-measured)

- `resultsPerPage=5000` → **HTTP 404, EMPTY body**, error text only in the
  `message` RESPONSE HEADER: `resultsPerPage parameter cannot exceed 2000.`
- 130-day window → **HTTP 404, empty body**, header:
  `message: Date range cannot exceed 120 days.`
- (S6 addendum) wrong/missing-but-expected key → 404 too. **NVD says 404
  for at least three unrelated client errors** — the client must read the
  `message` header to tell them apart; an empty-body 404 is NEVER
  "no such CVE" (that is a 200 with `totalResults: 0`).

### Rejected CVEs are in the delta stream

`CVE-2024-7038` (arrived via the delta window): `vulnStatus: "Rejected"`,
`metrics: {}` (empty), en description is the literal boilerplate
`"Rejected reason: This CVE ID has been rejected or withdrawn by its CVE
Numbering Authority."` `vulnStatus` values seen in one window: Analyzed,
Deferred, Rejected.

## What our code must therefore do

- Chunk catch-up gaps into **≤120-day windows**; page each window with
  `resultsPerPage ≤ 2000` + `startIndex` until `startIndex ≥ totalResults`.
- Treat 404 as a client/config error: read the `message` header, log it,
  do NOT advance the watermark; retry later. Body may be empty — never
  `json.loads` a 404 body.
- Skip (or tombstone) `vulnStatus == "Rejected"` docs — do not index
  boilerplate as knowledge. Keep the skip count in ingest stats.
- Space requests ~3–6 s even keyed (NVD bulk-pull etiquette from probe 1);
  the scheduler sleeps between pages, never races the 50/30 s quota.
- Watermark = the window's `lastModEndDate` (only after ALL pages of the
  window landed), not per-page.
