# S29 Step 0 — adversarial review of S28's own code (2026-10-14)

_S29 (backend), Step 0 item 3. S28 shipped D-046…D-050, `e2af082`, and the
review fixes `831dedc` and `3a09fcd`. Each change was mutant-checked or
battery-judged by its author; nobody else had read it adversarially. Every
integration action in this phase will run through this code._

## Method

- **Four fresh, read-only reviewers, one per area**, launched in parallel with
  no access to the S28 transcripts: the D-046 budget and `knows()`; D-048's
  doors and `831dedc`; D-049's `record` path (with B2's later changes to the
  same payload); D-047/D-050's regexes and `e2af082`'s alert keys. They ran
  pure Python against the repo's own fakes; no DB, network or engine.
- **Every finding was reproduced by execution in this session before anything
  was fixed.** One needed Postgres (the verdict overwrite), reproduced with a
  temporary test against the dev DB, then deleted.
- **Fixes: a test that failed first, a mutant run on each guard, the full gate,
  then a fifth fresh reviewer read the fix commits** (section at the end).
- The reviewers' scripts are kept in `docs/probes/s29-review/` so each result
  can be re-run (`PYTHONPATH=tests .venv/bin/python <script>`).
- **No engine calls.** Zero inference spend.

## The fixes, in one line each

- **`8187925`**: possessive whitespace (`\s*+`) after a lead-in word in both
  rules. Same language: 0 of 58,707 differential-fuzz inputs differ between old
  and new. The D-047 and D-050 operating points still hold. 55-char identity
  input and 8,000-space note input now < 50 ms (pinned).
- **`14bafba`**: an `unknown` verdict does not replace a known label; the
  sighting is still recorded (`last_seen`), and a FIRST `unknown` is still
  written, as D-055 kept. Reproduced live first: latest label `unknown`, flip
  `malicious → unknown`.
- **`b069b84`**: from a cut snippet, only indicators the whole hit text also
  names count as supplied. An indicator shown whole ahead of the cut still
  counts (pinned).
- **`6750028`**: a step whose every call was refused for budget goes to the
  tool-free synthesis pass, in `run` and `run_stream`. A step where any call
  ran goes on (pinned). Mutant caught 2/2.
- **`39908b5`**: the "last call" notice goes on the call that spends the budget,
  whatever its status. Mutant caught.
- **`d16afaa`**: `alert.name` and `detection.name` named one by one after
  `rule.name`, never "any `.name`".

## Cleared (sound, with the proof the reviewers cited)

- **D-046.** `run`/`run_stream` count, offer and refuse identically; the
  counter is per turn and never shared (`loop.py`, `chat.py:886-900`); no call
  counted twice; unknown tools and actions never counted; parallel calls with
  one slot left run exactly one and carry the notice; no empty `tools: []` or
  stray `tool_choice` is sent; a refused call has no side effects (no D-049
  record, no spend row). `knows()` returns True only for platform-registered
  names; invented names still log as `<unregistered>`.
- **D-048.** Every state change is one conditional UPDATE gated on status,
  claim and age; run-now vs withdraw, two run-now clicks, run-now vs approve's
  own run and withdraw vs a late approve each have exactly one winner. Staleness
  uses the DB clock only, with the same strict `<` everywhere. Run-now re-runs
  `check_executable`. Every statement filters `workspace_id`; a foreign id is a
  404 like a missing one. Claims mint and match tokens; `resolved_by` is written
  without touching `decided_by`. `withdrawn` is terminal everywhere, page
  included. One status-CHECK block. `831dedc`'s `contended` can only fire on a
  row that moved and came back; no legitimate undo is refused.
- **D-049.** The lambda closes over the request's own pool and frozen
  `AuthContext`; the model's arguments cannot reach `workspace_id`. Only
  allowed indicators are recorded. `NetworkContext` is never persisted. An
  "unknown" is never stored as benign. Reserved space is skipped. A failed
  record tells the model `false`, with no exception text. The IOC shortcut and
  the agent never both run in one turn. Nothing new joined the rail's index.
- **D-047/D-050/`e2af082`.** `IDENTITY_COPY` names no model or vendor. "who made
  the Emotet malware?", "which company created Cobalt Strike?", "what model of
  firewall is this?" all go deep. IOC messages containing note words keep the
  shortcut. Format detection beats keywords. `_NOTE_ASK_RE` is linear. The
  normaliser never raises (deep nesting, NaN, 1e400 all degrade to DEFERRED);
  an ECS alert is named by its rule; dotted and nested keys behave the same.

## The fifth review (of the fixes)

A fresh read-only reviewer attacked the six fix commits. It cleared most of
them by execution: 182,260 differential inputs found no change in what the two
classify rules match; the verdict skip loses no escalation, and nothing reads
`written`; the snippet fix changes neither the fields learned from nor the
payload the model sees; the budget stop's `for … else`, the claim before
synthesis and prompted mode are sound; `rule.name` still outranks the new
wrapper keys across Elastic, Suricata, Graph, CrowdStrike, Wazuh,
SentinelOne and Chronicle shapes; each new test fails on its parent.

**It found two real defects in `6750028`, both fixed with a test that failed
first:**
- **`47c3f35`**: `run_stream`'s final `done` event still said
  `step=max_steps`, so the route's `agent turn: steps=…` line read 8 for a
  3-call budget-stopped turn (the line that checks D-046's bound); `run` said 2.
- **`34fe9a1`**: the stop fired only when EVERY call in the step was refused.
  A refused call beside an unknown tool or malformed arguments went round again
  to the step cap (9 calls). Now any budget refusal in a step where nothing ran
  or was proposed ends the turn; a step of failures with no refusal goes on (a
  mutant dropping that half survived until a test pinned it).

**And logged:**
- **B-020**: after `14bafba` keeps a known verdict, the IOC copy and the
  agent's result still read "unknown … recorded", and nothing says the earlier
  verdict stands.
- **B-010 extended**: a third old rule, `_DOMAIN_CAND_RE`, takes 5.7 s on a
