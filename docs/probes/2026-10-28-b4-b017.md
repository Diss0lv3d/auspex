# 2026-10-28 — B4: B-017 before the fix (a malformed tool call crashes the turn)

Reproduced on `b4-bugs` (`c4dfdb6`) with the endpoint's raw body read by the
real parsers (`LLMClient.parse_completion`, `parse_sse_line` and
`accumulate_stream` in `auspex/llm/client.py`), then run through the real
`AgentLoop` with `FakeLLMClient` replaying the parsed result:

```
non-stream name: ['lookup_ip']
stream: TypeError can only concatenate str (not "dict") to str
loop: TypeError unhashable type: 'list'
```

- Non-streaming: `parse_completion` keeps `function.name` whatever its type;
  the loop's budget lookup (`auspex/agent/loop.py`, `_spent`) then raises on
  the list, and the turn dies.
- Streaming: `fold_stream_event` assigns any truthy name and `+=`s any
  truthy `arguments`, so an object-valued `arguments` raises before the loop.

The endpoint is the customer's (D-013, the platform adapts to it); its output
is not trusted to be well-formed.

## After the fix

Both parsers now read a tool call's id, name and arguments through
`_wire_text` (a non-string becomes its JSON text) and its parts through
`_as_dict` (a call or `function` that is not an object reads as empty).
The list-valued name reaches the loop as `'["lookup_ip"]'`, which names no
tool, so the loop answers "unknown tool" and the turn ends with an answer;
an object-valued `arguments` becomes its JSON. Tests:
`test_a_non_string_tool_name_parses_as_text_not_a_crash`,
`test_a_streamed_tool_call_with_object_fields_parses_as_text`,
`test_a_tool_call_that_is_not_an_object_parses_as_an_empty_call` (three
shapes) and the loop-level
`test_a_malformed_tool_name_from_the_endpoint_is_an_unknown_tool_not_a_crash`;
each failed first. 333 LLM, agent and chat tests pass.

## Review, and the streaming call list

The fresh review approved the fix and found the same symptom on the stream's
call list: `tool_calls` that is not a list of objects, and an `index` that is
a list (unhashable) or mixed with `None`/strings (unsortable), still raised.
`parse_sse_line` now reads the list and each call through the same guards and
folds a non-int `index` into call 0;
`test_a_streamed_tool_call_list_in_any_shape_never_crashes_the_fold` (four
shapes) failed first. The loop-level test now asserts the unknown-tool error
itself (its first assertion was always true). The review's wider findings, a
non-object reply envelope, `content` or `usage`, and the unknown name echoed
unbounded to the model, are B-035.
