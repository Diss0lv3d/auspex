# ENV_VARS — every variable, documented (rule: born here + .env.example simultaneously)

| Var | Purpose | Required | Default | Since |
|---|---|---|---|---|
| APP_ENV | `dev` or `prod`. Gates `/api/auth/dev-login` (dev only), `/api/docs` (dev only), and SECRET_KEY strictness | no | `dev` | S0 |
| DATABASE_URL | Postgres DSN (transactional truth; D-001). In compose: `postgresql://auspex:auspex@postgres:5432/auspex`; from host (tests): port `55432` | no | compose-internal DSN | S1 |
| OPENSEARCH_URL | Our OWN OpenSearch container (D-009); SARA's cluster is reference-only, its creds never appear here | no | `http://opensearch:9200` | S0 |
| OPENSEARCH_USER / OPENSEARCH_PASS | Basic auth for real clusters. Local dev container runs `DISABLE_SECURITY_PLUGIN=true`, so these are ignored locally | no | empty | S0 |
| LLM_BASE_URL / LLM_MODEL / LLM_API_KEY | Customer-supplied OpenAI-compatible endpoint (D-005). Loaded by config since S1, first used in S2. **`LLM_BASE_URL` is the API root exactly as the provider documents it for the OpenAI SDK (D-033)** — e.g. `https://<host>/v1`, `https://api.z.ai/api/paas/v4`; the platform appends only `/chat/completions` and `/models`, never a version segment. **Dev primary (D-034):** `glm-4.5-air` on Z.ai's general pay-as-you-go API, `LLM_BASE_URL=https://api.z.ai/api/paas/v4` — a public URL that resolves identically from host and container (so `auspex.devhost` does NOT pin it; `.env` is the single source of truth). Never the Coding Plan endpoint, never KSA-tenant data. (Scout on Northflank, D-015, is decommissioned.) **Dev secondary/offline (D-013):** local Ollama `qwen3:14b` — set `LLM_BASE_URL=http://host.docker.internal:11434/v1` (container; compose `extra_hosts: host-gateway`) or `http://localhost:11434/v1` (host runs). Secrets never committed — `.env` and `.env.bak-northflank` are gitignored | no (until S2) | empty | S0 |
| LLM_AUTOPROBE_ENABLED | D-038. `true` ⇒ a background startup task probes the configured endpoint (LLM_BASE_URL + LLM_MODEL) once per fingerprint, **and again whenever the newest measurement is over 7 days old (D-042; checked every 6 h while the app runs)**, with the capability battery (`auspex/llm/capability.py`, ~15 requests of the customer's inference) and records the deployment scorecard that chooses native vs two-pass reasoning (D-016) and the agent path (D-037). A probe that measured nothing (unreachable, or basic chat failed — e.g. a wrong key) is NOT recorded and is retried on a schedule. `false` ⇒ nothing probes; deep turns stay conversational unless `scripts/llm_harness.py` wrote the scorecard. Host/test runs pin `false` via `auspex.devhost` (hermetic) | no | `true` | S26 |
| GLM_API_KEY | **Dev-only.** Burhan's Z.ai **pay-as-you-go** key under its own name (S26, D-034). Read by the `docs/probes/s26-zai/` probes and referenceable as a dev-registry `api_key_env`; the app itself reads `LLM_API_KEY`, which holds the same value while Z.ai is the dev primary. Never a Coding Plan key — its terms forbid use behind our own application. Never printed, never committed | no | empty | S26 |
| DEV_LLM_REGISTRY_FILE | Path to a gitignored JSON file listing endpoints for the **internal, dev-only** model switcher (D-016). Loaded only when `APP_ENV=dev`; empty ⇒ switcher off (prod never loads it). Keys are referenced by env-var name inside the file, never inlined. Template: `dev-endpoints.example.json`. Not customer-facing (org policy: multi-LLM stays internal) | no | empty | S3 |
| ENRICHMENT_ENABLED | Master switch for the S5 enrichment fan-out. `true` ⇒ keyless providers (InternetDB, CIRCL hashlookup, OTX) run on every ioc_check turn; key-gated providers join when their key exists. Host test runs pin this `false` via `auspex.devhost` so CI never touches live providers | no | `true` | S5 |
| ABUSECH_AUTH_KEY | abuse.ch Auth-Key — ONE key (free, auth.abuse.ch) activates BOTH URLhaus and ThreatFox. Keyless calls have been 401 since abuse.ch locked their APIs (probe 2026-07-16) | no | empty | S5 |
| ABUSEIPDB_API_KEY | AbuseIPDB APIv2 key; activates the AbuseIPDB provider (free tier 1 000 checks/day) | no | empty | S5 |
| OTX_API_KEY | AlienVault OTX key, sent as `X-OTX-API-KEY` when present. OTX answers keyless (probed live), so this only raises rate limits — the provider is active either way | no | empty | S5 |
| GREYNOISE_API_KEY | GreyNoise key; activates the GreyNoise community provider. Keyless community access is 25 lookups/week (probed) — too small to ship, hence key-gated | no | empty | S5 |
| KB_ENABLED | Master switch for the S6 knowledge base (auspex-knowledge index + server-side embeddings, D-018). `true` ⇒ app startup runs the idempotent KB bootstrap (ML cluster setting, model register+deploy — ONNX pinned, index create, seed ingest) and cve_lookup/definition shortcuts consult the KB. Host test runs pin this `false` via `auspex.devhost` (hermetic; KB mockable at `app.state.kb`). First boot on a fresh volume downloads the embedding model (~12 s) from artifacts.opensearch.org | no | `true` | S6 |
| NVD_API_KEY | NVD CVE API 2.0 key, sent as the `apiKey` request header. Raises the rate limit 5→50 req / rolling 30 s (probe-verified live 2026-07-17: wrong key → 404, keyed 9-request burst all 200). Read by S7's NVDFeed (delta + single-CVE fetches) | no | empty | S6 |
| INGEST_ENABLED | Master switch for the S7/S8 feed-ingestion scheduler (NVD delta + CISA KEV + FIRST EPSS → enriched per-CVE KB docs; **plus MITRE ATT&CK Enterprise STIX → technique/tactic docs, S8**). `true` ⇒ a background startup task runs the KB bootstrap, catches up missed windows from the `ingest_state` watermarks (multi-day gaps chunked at NVD's 120-day limit), then cycles hourly. **Egress required: nvd.nist.gov, cisa.gov, first.org, and `raw.githubusercontent.com` (the ATT&CK bundle — commonly blocked by SOC egress policy; a block degrades honestly since the ATT&CK phase is isolated from the CVE feeds, S9 review).** No per-feed switch yet. Inert unless KB_ENABLED — the scheduler needs the KB to write into. Host/test runs pin `false` via `auspex.devhost` (hermetic; scheduler mockable at `app.state.ingest`) | no | `true` | S7 |
| SECRET_KEY | JWT signing key (HS256). **Required when APP_ENV=prod**; in dev, a missing key falls back to an ephemeral per-process key (tokens die on restart). Generate: `openssl rand -hex 32` | prod: yes | none (dev: ephemeral) | S1 |
| JWT_TTL_MINUTES | Session JWT lifetime in minutes | no | `720` | S1 |
| GOOGLE_CLIENT_ID / GOOGLE_CLIENT_SECRET | Google OAuth web client. Both empty ⇒ OAuth endpoints return 503 "not configured" (config-stubbed) | no | empty | S1 |
| GOOGLE_REDIRECT_URI | OAuth callback URL registered with Google | no | `http://localhost:8000/api/auth/google/callback` | S1 |
